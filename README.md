# 누리지음 퍼블리싱 키트

- 기준: `71d77aa522`, 2026-11-04
- 대상: 「CMS 관리 통합 시안」의 새 기능 화면. 서버 없이 `index.html`을 더블클릭해서 엽니다.
- 데이터: 전부 목데이터입니다. 저장·조회는 동작하지 않습니다.

## 폴더

| 폴더 | 내용 | 수정 |
|---|---|---|
| `pages/` | 화면·탭·모달 상태별 HTML. 머리 주석에 반영 위치가 있습니다 | 가능 |
| `static/` | 저장소 `static/`과 같은 경로의 실제 CSS·JS | 가능(`vendor/krds/` 제외) |
| `static/admin-ui/v2/new-features.css` | 새 기능 화면 전용 CSS | 가능 |
| `static/admin-ui/v2/pub.js` | 로컬 미리보기 전용 스크립트. 실제 콘솔에 들어가지 않습니다 | 불필요 |
| `reference/` | 통합 시안 원본(참고용). 아래 「시안과 다른 곳」을 먼저 보세요 | 불필요 |

## 수정 규칙

1. `nv-*` 클래스 이름과 `data-*` 속성을 유지합니다. 스크립트가 여기에 걸려 있습니다.
2. `vendor/krds/`는 고치지 않습니다.
3. `cms-admin-v2.css`·`cms-design-system.css`에는 색상값을 직접 쓰지 않고 `--cms-*` 토큰만 씁니다. 새 값은 `shared/nuri-tokens.css`에 추가합니다.
4. 고친 `static/` 폴더와 `pages/`를 그대로 돌려주세요. 개발팀이 경로대로 비교해 반영합니다.
5. HTML은 개발팀이 서버 템플릿으로 옮깁니다. 표와 입력 칸의 구조는 유지하고, 글자 값은 목데이터로 봐 주세요.

## 시안과 다른 곳

2026-11-04 콘솔 메뉴 목록이 시안보다 우선입니다.

- 「CMS 메뉴 관리」 → 「메뉴관리」, 「접속 기록」 → 「접속기록」, 「사이트」 → 「사이트 관리」
- 「관리자메뉴관리」는 만들지 않습니다.
- 이미지, 부서 및 조직, 운영 진단, 연결 서비스 링크는 사이드바에서 숨깁니다.
- 그룹묶음(부서): 권한그룹 명단에 부서를 넣으면 부서원이 자동으로 포함되는 안을 화면에 그렸습니다(명단 · 패널). 개발 확인이 필요합니다.
- 서브관리자 등록은 직접 입력 + 임시 비밀번호입니다. `pages/auth-account-add.html`은 시안에 없고 현재 콘솔의 관리자 계정 등록 패널에서 가져왔습니다. 연락처·부서명·이메일 칸은 목록 표와 메뉴 담당자 칸에 맞춰 더했습니다.

## 개선 작업(2026-11, 피그마 「추가기능」 페이지 기준)

단계별로 키트에 반영합니다. 각 단계는 별도 커밋입니다.

- 1단계 공통 부품: `new-features.css` 끝 「개선 1단계 공통 부품」, 모양은 `pages/ui-parts.html`. 저장 영역(`.savehead`) · 사유 입력 줄(`.reasonbar`) · 바뀐 항목 표시(`.chg`) · 저장 안 한 탭 점(`[data-dirty]`) · 탭 이동 확인(`.leavepop`) · 알림(`.ntoast`) · 검색 옵션창(`.pick`) · 작은 체크 목록 창(`.checkpop`). 새 토큰 `--cms-change-dot` · `--cms-change-border`.
- 탭: 키트의 모든 탭(`.gtabs` — 1단계 메뉴 · 권한 · 게시판 · 접속기록 · 수정 화면)을 피그마 「nuri/밑줄 탭」 모양으로 바꿨습니다. 마크업은 그대로이고 `new-features.css` 「탭: 밑줄 탭으로 통일」 규칙만 더했습니다.
- 저장은 탭마다 따로 합니다. 머리 막대 버튼 이름에 탭 이름을 붙입니다(「메뉴 정보 저장」). 사유는 아래 떠 있던 저장 막대 대신 머리 막대 아래 사유 입력 줄에서 받습니다.
- 2단계 메뉴관리(피그마 01~05 섹션): `new-features.css` 끝 「개선 2단계」 규칙. 화면은 `index.html`의 메뉴관리 묶음.
  - 수정 화면 틀(`.edx`): 위 흰 막대(← 메뉴 수정 + 탭별 저장) → 바꾼 내용이 있을 때만 사유 줄 → 흰 카드 한 장(위치 · 단계 번호 · 메뉴명 · 누리집에서 보기 · 이전/다음 · 탭 · 본문 2단). 3단계 게시판 수정도 이 틀을 씁니다.
  - 아래 떠 있던 저장 막대(`.savebar`)는 메뉴 수정 화면에서 뺐습니다. 「수정 이력」 탭은 저장할 것이 없어 저장 버튼을 두지 않습니다. 소스 수정의 위 「소스 저장」은 저장하고 다음 버전으로 게시하고, 아래 「임시저장」은 비공개로만 저장합니다.
  - 담당자: 「담당자 변경」 → 칸 아래 검색창 + 옵션창(이름 · 아이디) → 더 찾을 때 「상세 검색」 모달. ✕로 비우면 담당자 없이도 저장할 수 있고, 빠지는 관리자 권한을 미리 알려 줍니다.
  - 이미지 삽입: 폴더 · 파일 이름으로 찾고 썸네일로 고릅니다. 대체 텍스트가 없으면 「꾸밈용 그림」을 고르기 전까지 넣을 수 없습니다. 썸네일은 목데이터라 아이콘으로 대신했습니다.
  - 접근권한 공통안: 「상위 메뉴와 같게」는 체크 한 줄, 표 오른쪽 ✕로 줄 빼기, 「권한그룹 추가」 · 「관리자 권한 추가」는 버튼 + 찾기 목록. 회원 권한그룹은 관리자 권한에 넣을 수 없게 흐리게 보입니다. 오른쪽 「적용 요약」.
  - 메뉴 목록: 행 작업은 「관리▼」 대신 ⋮ 버튼(항목은 그대로), 메뉴명 아래 경로 줄은 뺐습니다. 단계 번호 색은 1→4 남색 · 파랑 · 연파랑 · 회색. 이 표 모양(`.nv-nav-table`)을 함께 쓰는 게시판 목록의 제목 색도 검정으로 맞춰졌습니다.
- 3단계 게시판 수정(피그마 08 · 12 섹션): 메뉴 수정과 같은 틀(`.edx`)에 게시판 항목을 넣었습니다. 「게시판 정보 저장」 · 「접근권한 저장」 + 사유 줄, 오른쪽 「게시판 설정」 열. 접근권한은 메뉴 공통안과 같은 부품이고, 여기서 고쳐도 연결 메뉴(알림마당 › 공지사항)와 함께 바뀝니다. 연결 메뉴는 메뉴 접근권한으로 가는 링크 칩입니다.
- 4단계 권한 묶음(피그마 06 · 09 · 10 · 11 섹션): `new-features.css` 끝 「개선 4단계」 규칙.
  - 권한그룹명단관리: 권한그룹을 버튼형 선택 칸 + 찾기 목록으로 고르고, 검색 한 칸에서 사람 · 부서를 찾아 바로 넣습니다. 표는 구분 · 이름 · 소속 · 기간 · 권한 부여일 · ✕. 바뀐 것은 바로 저장됩니다.
  - 서브관리자관리: 상태 칩(전체 · 정상 · 접속 제한)으로 거르고, 권한그룹은 배지 + 연필(작은 체크 목록 창, 바로 저장). 비밀번호 초기화 · 접속 제한 풀기 · 계정 폐기는 ⋮에 모았고, 폐기는 확인 창을 거칩니다.
  - 서브관리자 등록 패널: 위 설명대로 두 방법을 나란히 두고, 회원을 고르거나 확인해야 권한그룹 선택과 「서브관리자로 등록」이 열립니다.
  - 권한그룹관리 패널(`group-panel*.html`): 메뉴 접근권한의 「권한그룹관리」에서 열면 체크해 「「공지사항」 접근권한에 추가」로 바로 넣습니다. 이미 들어 있는 그룹은 「이 게시판에 있음」, 관리자 권한에서 열면 기본 · 회원 권한그룹은 고를 수 없습니다. 권한 화면에서 열면(`auth-group-panel.html`) 체크와 추가 버튼이 없습니다. 상세는 명단 · 누리집 접근권한 · 관리자메뉴 탭.
  - 메모: 「여러 명 한번에 고르기」(피그마 07)는 제안이라 버튼만 두었습니다.

## 알아 둘 점

- 툴팁 문구에는 시안의 출처 표기(당진·국특원)가 남아 있습니다. 문구는 개발 때 정리합니다.
- 소스 수정 탭의 편집 영역은 시안의 간이 편집기입니다. 실제 콘솔은 SunEditor를 씁니다.
- KRDS `component.css`는 라벨 안의 맨몸 체크박스를 `!important`로 숨깁니다. `new-features.css` 끝에 표 칸·칩 체크박스를 되살리는 규칙이 있으니 지우지 마세요.
- `reference/`의 시안에는 설명 페이지와 외부 링크가 그대로 있습니다. 전달 범위를 정할 때 참고하세요.
- `new-features.css` 끝의 「표 행 버튼 시각 정돈」 규칙은 표에서 행마다 반복되는 「관리▼」와 작은 위험 버튼(계정 폐기·삭제)의 테두리·배경을 평소엔 걷고, 행에 마우스를 올리거나 포커스가 들어오면 원래 모양으로 되돌립니다. 마크업은 바꾸지 않았습니다.
